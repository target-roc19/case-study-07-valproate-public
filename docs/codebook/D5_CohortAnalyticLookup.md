## Processing Logic

1. Load enabled analysis rows (enabled=TRUE) from outcome_analysis_types.csv.
2. Load all required follow-up and weight datasets referenced by source_fup and source_weight.
3. For each enabled analysis row:
   - Filter follow-up dataset to rows matching the target estimand,
   - Extract follow-up columns (fup, pm, eventCount) for the selected estimand,
   - Merge weights when source_weight is specified, using the weight_col to select the weight variable,
   - Split dataset by listed_by variable when listed_by is non-empty,
   - Run CohortAnalytics::compute_rates_cohort per split with outcome model type from risk_type.
4. Apply pooling_method per analysis row:
   - rubin: pool estimate/CI triplets with mice::pool.scalar across imputation_id splits,
   - subset: filter rows using pooling_condition expression (e.g., bw_id == 1),
   - (empty): keep rows as produced, no pooling.
5. Concatenate pooled list elements to D5_CohortAnalyticLookup.
6. Keep split-tracking columns imputation_id and bw_id in the saved D5 output for traceability.

## Weighting Rules

Weighting strategy by analysis (source_weight and weight_col from metadata):

- **Analyses 1, 1a, 1d, 2, 2d**: IPTW from D4_StudyCohort_IPTW or D4_StudyCohort_CombinedWeights

  - 1, 2, 1d, 2d: stabilized_iptw from D4_StudyCohort_IPTW
  - 1a: iptw_ipsmw from D4_StudyCohort_CombinedWeights (Propensity Score Matching Weight)
- **Analysis 1b, 2b**: IPTW from D4_StudyCohort_IPTW (best/worst case scenarios)

  - stabilized_iptw, no imputation pooling
- **Analysis 1c, 2c**: Time-varying IPTW from D4_PS_Weights_IPTW_tv (disabled)

  - stabilized_iptw_tv
- **Analysis 1e, 2e**: Maternal-adjusted IPTW from D4_StudyCohort_CombinedWeights (disabled)

  - stabilized_iptw_mother

## Processing Steps

`transformations/T4_statistical_analysis/source_code/compute_outcome_analyses.R` reads the enabled analysis definitions and outcome parameters from the T4 metadata files. For each analysis it loads the configured follow-up and weight datasets, selects the estimand-specific columns, applies the requested weight, and runs the CohortAnalytics rate and cumulative incidence ratio calculations. It then performs Rubin pooling or the configured BW subset operation, retains analysis and split identifiers, and writes the pooled, unpooled, and BW lookup CSVs used by downstream report tables.
