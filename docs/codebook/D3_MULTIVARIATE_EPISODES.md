## Metadata

| Table name                | D3_MULTIVARIATE_EPISODES |
| ------------------------- | ------------------------ |
| Description               | Aligned episode intervals with eligible study-variable values in separate columns. |
| Source                    | `D3_UNIVARIATE_EPISODES` and RWEBRIDGE:`study_variables`. |
| Step                      | `transformations/T3_study_design/source_code/create_multivariate_episodes.R` |
| Content                   | Person-level intervals with time-aligned study-variable values and an `SV_SEX` column. |
| Population                | Persons present in the input univariate episodes; the multivariate pipeline is called with `person_ids = NULL`. |
| Unit of Observation (UoO) | One person and aligned episode interval. |
| File format               | Parquet file (`D3_MULTIVARIATE_EPISODES.parquet`). |

## Processing Steps

This script filters the study-variable metadata to eligible variables except those with `concept_source == "D3_SPELLS"`, runs `episodeR::multivariate_episodes_pipeline` over `D3_UNIVARIATE_EPISODES_parquet/` with no person-ID restriction, adds `SV_SEX` as a constant TRUE boolean column, and writes `D3_MULTIVARIATE_EPISODES.parquet`.

1. Load eligible study-variable metadata except variables whose `concept_source` is `D3_SPELLS`; normalize look-back values and set `batch = FALSE`.
2. Run the multivariate episode pipeline on the partitioned univariate episodes with `person_ids = NULL`, so no explicit person filter is passed. The pipeline aligns intervals and pivots variable values into columns.
3. Add `SV_SEX` as a boolean column and set it to `TRUE` on every row. Although `study_variables.csv` describes `SV_SEX` as `CHARACTER`, this script does not join the actual sex values from `D3_SPELLS`.
4. Write `D3_MULTIVARIATE_EPISODES.parquet` under the configured D3 output directory.

The current eligible output variables are thosed flagged as `TRUE` in RWEBRIDGE:`study_variables/eligibility`, and the script-added `SV_SEX`.
