## Processing steps

1. Allocation to trials

From D3_ELIGIBILITY, we take all rows where `eligible_exposed = TRUE` `OR` `eligible_control = TRUE`. We then assign them to monthly trials. This is done in two steps.

First, one monthly trial is defined per month since January 2010 until March 2016. This implies 75 monthly trials in total. Each trial starts on the first day of a given month and ends on the last and is assigned one integer from 1:75, in chronological order; a variable `trial_start` and `trial_end` will be created per trial representing the first and last day of the month, respectively.

Seconds, individuals are enrolled in trials. This is done by checking if a spell (i.e. a row) from D3_ELIGIBILITY with `eligible_exposed = TRUE` `OR` `eligible_control = TRUE` does not satisfy other two requirements.

- `(start < trial_start AND end < trial_start)` This means the total duration of the eligible spell happened before the start of trial. If true, individual is not eligible for that trial.
- `(start > trial_end` This means the total duration of the eligible spell happened after the start of the trial. If TRUE, individual is not eligible for that trial
  Note that in any other circumstance, part of the spell will overlap with the trial duration, meaning the individual is eligible for that trial. This is exactly equivalent to checking that the rows satisfy this requirement:
- (`start < trial_start AND end > trial_start`) OR  (`start > trial_start AND start < trial_end`), which is also exactly equal to `start < trial_end` AND `end > trial_start`.  This last formulation is better for programming (e.g. using `data.table::foverlaps`) so it's what is implemented in code

In the event that an individual is eligible multiple times for a given trial, the earliest eligible time will be selected. When multiple distinct eligible spells from D3_ELIGIBILITY are concerned, the spell with the earlier start date is selected. Once a spell is selected, T0 will then be computed as max(trial_start, start_date). Code for bootstrapping is cohort selection is available, but it was not implemented in last code version.

2. Addition of child information

Once all males are allocated to trials, the children information is added by merging with D3_FatherChild. Concretely, we add the information on whether an individual conceived a child within 3 years of time-zero, what was the earlist conception date and date of birth after T0, and wether an individual had a livebirth within 3 years and 9 months after T0.

## Example

See two examples. The first one is an [example without boostrapping](/tests/testthat/test_data/D4_StudyCohort/D4_StudyCohort.csv) . This example is connect to the example used in the D3_ELIGIBILITY codebooks. It displays how the spells for individuals that are eligible at some point (ids 1, 3 and 5) are assigned to the sequential trials. Person 5 is enrolled in multiple trials (all corresponding to a long spell, 18 month spell). Person 3 is enrolled in only one trial, and person 2 is enrolled in two trials (both with the same spell. Two spells could be part of the same trial, for which the earlier spell is selected).

The second example is an example of a [bootstrap iteration](/tests/testthat/test_data/D4_StudyCohort/D4_StudyCohort_bootstrap.csv) . It is a hypothetical iteration corresponding to a bootstrap resample: 5,1,1. I.e., individual 2 is selected twice, therefore their spells are included twice. This is reflect in the **`boot`** and **`boot_person_id`** variables.
